# Implementation Summary: YouTube Event Dating, Citation Filtering, and Pipeline Selector

## Overview
Implemented three major features for the beta release:
1. **YouTube event date extraction** from video descriptions for accurate event dating
2. **Citation-based document filtering** to show only referenced documents prominently
3. **User-facing pipeline selector** for A/B testing comparison between Fast and Baseline engines

---

## 1. YouTube Event Date Extraction

### Files Changed
- `oracle/src/services/youtube_service.py`

### Changes Made
- **Added `extract_event_date_from_description()` method** (lines 213-285)
  - Parses "Streamed live on {date}", "Premiered {date}", "Live on {date}" patterns
  - Extracts actual event dates separate from upload dates
  - Returns `event_date` (ISO format), `date_type` ("livestream" | "premiere"), and confidence (0.95)
  - Validates year range (2020-2030)

- **Refactored fallback event extraction** into separate `_extract_fallback_event()` method
  - Cleaner separation of concerns
  - Uses publish_date year when explicit year not in title

### Usage
Videos can now be linked to events with accurate dates:
- Video segments retain timestamps for deep-linking (e.g., `&t=330s` for 5:30)
- Parent event provides context (e.g., "Cisco AI Summit - Feb 4, 2026")
- Upload date vs event date properly distinguished

## 2. Citation-Based Document Filtering

### Files Changed
- `oracle/src/services/response_generator.py`
- `frontend/src/components/QueryResultDisplay.jsx`
- `frontend/src/components/QueryResultDisplay.css`

### Changes Made

#### Backend (`response_generator.py`)
- **Enhanced `_extract_citations()` method** (lines 108-147)
  - Now returns `tuple[list[Citation], set[int]]` with cited document indices
  - Tracks which documents were actually referenced with [N] markers

- **Added `filter_documents_by_citations()` method** (lines 149-183)
  - Separates documents into cited (max 10) and additional context (max 5)
  - Returns structured tuple: `(cited_docs, additional_docs)`
  - Logs filtering results for analytics

#### Frontend (`QueryResultDisplay.jsx`)
- **Updated References section** (lines 563-646)
  - Shows "References (Cited in Answer)" header
  - Cited documents display prominently with [N] markers
  - Added collapsible "Additional Context" section for non-cited documents
  - Limits additional context to 5 documents
  - Preserves full context while emphasizing relevance

#### Styling (`QueryResultDisplay.css`)
- **Added Additional Context styles** (lines 711-757)
  - `.additional-context-section` with dashed border separator
  - `.additional-context-header` with hover effects
  - `.reference-item.additional` with subtle opacity and left border
  - `.reference-summary` for document summaries in collapsed view

### User Experience
- Users now see only directly referenced documents by default (5-10 documents)
- Additional context available via collapsible section
- Clearer understanding of which sources were actually used in the answer
- Reduced information overload while maintaining transparency

## 3. User-Facing Pipeline Selector (Beta Feature)

### Files Changed
- `oracle/src/models/request.py`
- `oracle/src/services/ab_test.py`
- `oracle/src/routes/query.py`
- `frontend/src/pages/Chatbot.jsx`
- `frontend/src/pages/Chatbot.css`
- `frontend/src/services/api.js`

### Changes Made

#### Backend API Schema (`request.py`)
- **Added `pipeline_override` field to `QueryOptions`** (lines 86-89)
  - Type: `Optional[Literal["fast", "baseline"]]`
  - Default: `None` (uses A/B test)
  - Description: Override A/B test pipeline selection

#### A/B Testing Logic (`ab_test.py`)
- **Enhanced `should_use_fast_pipeline()` function** (lines 11-33)
  - Added `pipeline_override` parameter
  - Checks override before hash-based bucketing
  - Logs override usage for analytics
  - Maintains deterministic A/B test when override is None

#### Query Routing (`routes/query.py`)
- **Extract pipeline_override from request options** (lines 265-280)
  - Passes override to `should_use_fast_pipeline()`
  - Sets telemetry attributes: `oracle.pipeline_override_used`, `oracle.pipeline_override_value`
  - Logs pipeline selection with override context

#### Frontend State Management (`Chatbot.jsx`)
- **Added `pipelineMode` state** (lines 26-30)
  - Values: "system", "fast", "baseline"
  - Default: "system" (A/B test)
  - Persisted to localStorage

- **Added `setPipelineMode()` wrapper** (lines 49-53)
  - Syncs state with localStorage

- **Pass `pipelineOverride` to API** (lines 303-310)
  - Converts "system" → null for A/B test
  - Passes "fast" or "baseline" as override

#### Frontend UI (`Chatbot.jsx`)
- **Added Pipeline selector dropdown** (lines 730-742)
  - Positioned after Personalize dropdown
  - Options: "Engine: System (A/B)", "Engine: Fast", "Engine: Baseline"
  - Tooltip: "Fast uses instant templates, Baseline uses comprehensive LLM synthesis, System auto-selects"
  - Disabled during loading

#### API Client (`api.js`)
- **Added `pipeline_override` to payload** (line 232)
  - Maps `pipelineOverride` option to backend schema
  - Null value omitted (uses A/B test)

#### Styling (`Chatbot.css`)
- **Added dropdown styles** (lines 35-68)
  - Shared base styles for all dropdowns
  - Pipeline dropdown with green accent (`rgba(34, 197, 94, *)`)
  - Hover and disabled states
  - Consistent sizing and spacing

### User Experience
- Beta users can manually select pipeline to compare Fast vs Baseline
- Default "System" mode uses A/B testing for automatic selection
- Clear visual distinction (green border) for pipeline selector
- Tooltip explains differences between options
- Selection persists across sessions via localStorage
- Backend tracks override usage for beta feedback analysis
